One portal for operations, connectivity and support.

Hughes Web started as a way to reduce scattered lookups across spreadsheets, portals and external systems. It grew into a centralized operational portal with EACE, Hughes ON/cVortex, NOC, HelpDesk, monitoring, Omada, NCR, administration and indicators.

05

Architecture and engineering

Modular frontend

React 19, TypeScript, Vite, React Router, shadcn/ui and shared components.

Supabase core

Auth, PostgreSQL, operational history and Edge Functions for protected integrations.

Domain proxies

EACE and cVortex through Edge Functions; Omada through a proxy/serverless layer.

RBAC

admin > supervisor > operator with route protection and server-side validation for admin operations.

Operational observability

Dashboards, metrics, SLA, notifications and NOC views connected monitoring to daily work.

Technical documentation

Architecture, security, database, APIs, frontend, backend, authentication, operations and migration documentation.

Why this project matters

The project that changed the scale of what I was building.

Hughes Web was my first major project. It started from real pain in my own operational work and grew into a platform connecting multiple domains, integrations, access rules, dashboards and workflows.

It was also where I began treating development as an internal product discipline: understand operations, model data, integrate external systems, document decisions, care about security and evolve the experience without breaking users' workflows.
